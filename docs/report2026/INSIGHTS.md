# 핵심 발견 (2026-11-02, 데이터 2026-10-08~11-02)

모든 수치는 추출 CSV에서 직접 계산 — 정본은 같은 폴더 `stats.json`, 재현은 `tools/analyze.py`→`tools/rescore_h3.py`→`tools/resources.py`·검산 `tools/verify.py`(독립 검산 11항목 전체 일치).
표기 시각은 전부 KST. 통행량 절대치는 카운트 규칙 v3(10-17) 이후만, K2는 금지구역 재설정(10-20) 이후만 집계함(전후 비교 금지).
용어는 프로젝트 지도(docs/project-map.html) 정본을 따름 — Fast 모델(YOLO, '보는' 일) / Slow 모델(VLM, '왜 서 있는가' 판단) / Hybrid(결합). DB 열 대응: Fast 단독=YOLO_ONLY, Slow 단독=VLM_ONLY, Hybrid=HYBRID.

## 1. [Fast Loop이 만든 지표] 통행 패턴
- 등교 통행의 고비는 08:10–08:25의 15분임 — 피크 5분 칸은 08:20, 등교일 평균 66.1건/5분(2위 08:10 56.3, 3위 08:15 54.3)
- 등교 창 차량 흐름 650건/h는 주간 평시(07–19시 비창 471건/h)보다 38% 많음 — 하교 창은 582건/h
- 보행 통행(가상선 통과 기준)은 하교 창이 포함된 17시대에 최대임 — 차량 압력은 등교 창, 보행 노출은 하교 창에 몰림
- 규칙 v3 이후 16일간 차량 92,188건·보행 2,242건 계수함(차량 97.6%)

## 2. [Fast Loop이 만든 지표] 속도 (K1)
- 차량 속도 p85(100대 중 85번째로 빠른 차)는 28.9km/h로 어린이보호구역 제한(30km/h) 바로 아래, 중앙값 20.2km/h (표본 172,289건)
- 30km/h 초과가 12.1%, 40km/h 초과가 2.3% 존재함
- 과속은 통학 창이 아니라 심야에 집중됨 — 21~01시 초과율 16.1~18.5%(p85 30.5~31.0) vs 등교 창 10.9%(p85 28.1)
- 80km/h 초과 0.2%(344건)는 추적 오류로 추정되나 제외해도 초과율 12.0%로 결론 불변임

## 3. [Fast Loop이 만든 지표] 위험 이벤트 (K2·K3)
- K2(금지구역 정차)는 재설정(10-20) 이후 11일간 5,585건, 지속시간 중앙값 51.7초·p85 170초·최장 1.8시간, 낮 10–17시 전반에 분포함
- 정차 중 보행자 근접(person_near=1, 실측) 동반은 1.1%뿐임 — 위험 정의(정차∧보행자 통행) 기준 실제 '위험 정차'는 극소수
- K3(2m 이내 근접) 655건의 37.7%(247건)가 18–20시에 몰림 — 통학 창 내는 41건(6.3%)로, 체감(등교 중심)과 다른 발견임
- 근접 지점은 금지구역 언저리·화면 중앙 하단(횡단 지점)에 군집함(정규화 화면 좌표 기준, n=655)
- 사람 눈 대조에서 횡단 중 근접 미탐 2건 확인 — K3는 하한값임

## 4. [사람 눈 대조 검증] 신뢰도·수집 연속성
- 수동 대조 누적 판정 통과함 — 규칙 v3 확정 시각(10-17 14:45 UTC) 이후 16클립 Σ수동 596 vs Σ자동 552, 오차 −7.4%(기준 ±10%; 운영 정본 필터 = 공개 대시보드 신뢰도 카드와 동일 계산)
- 컷 이전 7클립(v2 규칙 자동값) 누적은 +137%로, 카운트 규칙이 v1 +393.8% → v3 −7.4%로 수렴했음을 보여줌(전체 23클립 혼합 합산은 +13.4%)
- 속도 대조 42건 평균 절대 오차 2.55km/h(기준 ≤3 통과)이나 건별 35.7%는 3km/h 초과(최대 10.2) — 개별 값 인용은 부적절함
- fps는 10-17 realloop 이후 중앙값 16.7, 목표(≥15) 달성 버킷 97.9%임
- 10-28~31 나흘 수집 공백(프레임 손상) 존재 — 같은 기간 qc=0(정상)으로 QC가 손상을 못 잡는 맹점이었음(corruptguard 도입 계기)

## 5. [Slow를 더한 Hybrid의 득실 ① 판정 품질] — 분석이 결합 규칙 회귀를 드러내고 수정으로 이어짐
- Fast 단독 기준선 정밀도 0.061·재현율 1.0으로 갱신됨(라벨 404건; 종전 0.077은 라벨 312건 시점) — 경보 100번 중 진짜 위험 약 6번
- 분석에서 간극 발견: 실 Slow 모델(llama.cpp·pv2, 10-20~) 시기 라벨 89건(전원 비위험 확정) 중 Hybrid(h2 기록)가 85건 위험 판정, 전체 위험 판정 89.3% vs 정차 person_near 실측 1.1%
- 코드 확인으로 회귀 확정·수정됨(11-02, 커밋 67e4060, 규칙 h2→h3) — 결합(combine)이 추적기 실측 person_near 대신 Slow 모델의 이미지 추측을 사용, 더미 태거가 실측을 메아리쳐 숨어 있던 결함. 수정: 실측 우선, 결측 시에만 Slow 관측 폴백
- h3 소급 재채점(수정된 규칙을 과거 live 정차 5,541건에 다시 채점 — 재료가 전부 DB에 있어 영상 없이 가능): 전체 위험 판정 4,950건(89.3%) → 61건(1.1%), 라벨 89건 기준 가짜 경보 85건 → 0건 — Fast 대비 오탐 억제 4.5% → 100%(재현: tools/rescore_h3.py)
- 단 양성 라벨 0건이라 정밀도·재현율 채점은 여전히 불가함 — h3 잔존 위험 61건(보행자 근접 동반 정차)의 진위도 미라벨. 오탐 억제만 검증된 상태로, 61건 우선 라벨링과 실가동 h3 기록 대조가 다음 단계
- Slow 모델 태그는 boarding 89.7% 쏠림·conf 전 구간 0.85 고정으로 판별 신호 부족(h3와 무관하게 남은 과제); unknown 0%(pv1 개선 목표 달성)
- 지연 p95 2,965ms로 목표(≤4,000ms) 통과, Slow 큐 드롭 0건

## 6. [Slow를 더한 Hybrid의 득실 ② 자원 비용] — 스왑 0으로 공존 성립, 여유는 약 1GB
- DB의 메모리·전력 열(mem_mb·power_w·swap_mb)은 모니터링 모듈 미가동으로 전부 공란임 — 자원 수치는 2026-11-02 13:12 KST경 기기 현장 스냅샷(tegrastats 2초 간격, Fast+Slow 상주 중)이 근거
- 전체 7,485MB 중 사용 6,265~6,282MB — Slow(llama-server) 상주 5,299MB(약 5.3GB), Fast 파이프라인+API(trafficsvc) 576MB
- 스왑 0MB(할당 자체 0) — 목표 '스왑 0'이 데이터로 입증됨
- 보드 입력 전력 6.29~6.37W(CPU+GPU+CV 1.6W), GPU 부하 56%↔0% 출렁(Fast 상시 추론), 온도 약 50°C
- DB 지연과 결합: Slow 판정 p50 2.9s·p95 3.0s(목표 ≤4s), fps 중앙 16.7·97.9%≥15 — 8GB 중 5.3GB를 Slow가 차지해도 스왑 0·fps 유지로 공존이 성립함
- 가용 여유 약 1GB뿐 — 더 큰 Slow 후보(Qwen3.5-9B)는 상주 교체 벤치로만 시험 가능함
