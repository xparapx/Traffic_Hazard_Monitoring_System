# Traffic 성과발표회 — 그림 디자인 시스템 (모든 에이전트 공통 브리프)

프로젝트: 공주고 STEAM 클럽, "엣지 AI 기반 통학 시간대 교통 위험 모니터링 시스템" —
Jetson Orin Nano 8GB(교내 창가, 교문 앞 도로 관측) + YOLO(TensorRT) 검출·추적 + 호모그래피 실측 좌표 +
VLM(Qwen3.5-4B) 하이브리드 판정 + 공개/관리 이중 대시보드 + 주간 리포트(LLM 제안·사람 승인).
핵심 설계: **영상을 저장하지 않는다**(enum JSON만 DB에) · VLM이 죽어도 K1~K3는 나온다.
심사 관점: 독창성·창의성, "데이터 기반 소셜 임팩트", 공동체 데이터 탐구 사이클 7단계.

선례: `Arduino_MQTT_MultiNode_Demo/docs/steam_report/v2/`(MintCap, 같은 발표회 양식)의 체계를 그대로 계승.
이 문서와 `design/base.css`만 다르고 규칙·렌더러(`render.mjs`)·파일 규약은 동일하다.

한 그림 안에서 속도는 항상 파랑, 정차는 항상 otan, 근접은 항상 gravy, YOLO는 항상 회색.

## 2. 글자 — 두 단계뿐
- 폰트: **IBM Plex Sans KR**(base.css가 로드, 렌더러가 폰트 로딩을 기다림).
- 보고서(`data-kind="r"`): 본문 10.5pt, 제목 12pt 굵게. 포스터(`data-kind="p"`): 본문 17pt, 제목 22pt 굵게.
- **그보다 작은 글자 금지** — 축 눈금·범례·각주·단위까지 전부 `--fs`. 안 들어가면 글을 줄이거나 그림을 키운다.
- 숫자는 tabular-nums. 단위는 숫자 뒤 반각 공백(30 km/h, 2.7 s).

## 3. 구성 원칙 (MintCap v2와 동일)
1. **한 그림 한 메시지** — `.t` 제목이 곧 결론 문장. 보조 설명은 `.t .sub`(회색).
2. **잉크 최소화** — 위·오른쪽 축선 없음, 가로 격자만, 테두리는 패널 하나.
3. **직접 라벨링** — 범례 상자 대신 선·영역 끝에 라벨.
4. **웹앱의 부품을 쓴다** — `.panel`, `.chip c-dwell` 등, `.dot`, `.num`, `.kpi`. 보고서 그림이 대시보드와 "같은 제품"처럼.
5. **여백** — 패널 안 글자는 가장자리에서 최소 1.6mm(r)/2.6mm(p).
6. **실제 크기로 만든다** — `<html data-w data-h>`(mm)가 곧 인쇄 크기. 넘침은 렌더러가 보고(OVERFLOW).
7. 글상자 나열 금지 — 흐름은 화살표·타임라인, 구조는 공간 배치, 수치는 KPI·막대로.
8. **프라이버시 불변식** — 그림·사진 어디에도 사람 얼굴·번호판이 보이면 안 된다. 도로 사진은 원경(식별 불가)만.
   그림 속 보행자·차량은 추상 아이콘/점으로. 주어에 "어린이·학생·학부모" 금지 → "보행자", "통행".

## 4. 파일 규약
```
design/base.css        공통 토큰·베이스 (수정 금지 — 보조 스타일은 각 HTML 안 <style>에)
figs/<name>.html       그림 1개 = HTML 1개. <html lang="ko" data-kind="r|p" data-w="159" data-h="60">
out/<name>.png         렌더 결과 — node render.mjs figs/x.html (인수 없으면 전부)
stats.json             분석 수치 정본(분석 에이전트 산출) — 글·라벨의 수치는 전부 여기서
```
- 이름 규칙: 보고서 `r_<id>.html`, 포스터 `p_<id>.html`, 도식 `d_<id>.html`(크기 변형은 r_/p_ 접두사만 다름).
- 외부 라이브러리 금지(인라인 SVG + CSS + 인라인 데이터). 렌더 후 PNG를 Read로 직접 열어 눈으로 확인.
- 렌더: `cd docs/report2026 && node render.mjs` (Edge 헤드리스, Node 24).
